# 0.5：实际使用后修复了什么

2026-10-13，作者 Agent 按使用者路径运行了本机服务与浏览器：选模板、确认资料、运行原版与改进版、执行中刷新、对比、点开失败证据、下载报告、逐题核对原文并提交开发者自测。使用真实 API、数据库、worker 和本地 Qwen，没有将开发者投票标为真人或客户验收。

## 页面与交互

前端从六个独立 HTML 页面收拢为一个 `index.html`。资料、运行、比较、评审通过 URL hash 切换；API 将旧地址重定向到对应步骤。CSS、API 客户端、问题中文释义和工作台逻辑分别维护。

| 实际遇到的问题 | 修复与验证 |
|---|---|
| 入口分散，难以知道下一步 | 四步导航、中文模板、资料预览、每步明确的下一步按钮 |
| 原文题目是英文，不易理解 | 显示中文释义；实际模型输入与冻结英文题目保持一致 |
| 已提交任务的响应尚未到达时刷新，任务找不到 | 发请求前保存幂等请求编号；刷新从项目 Job 列表恢复。浏览器故意延迟响应并刷新，找回同一任务 |
| 刷新丢失题集和对比选择 | 按项目保存当前题集、执行、实验、门禁和评审任务；刷新不触发新建 |
| 不同题集或不同评测器的版本混入对比 | 前端只显示兼容候选；后端仍独立验证兼容性 |
| 选择评审意见或输入理由时视图被重载 | 仅资料选择器触发加载；输入焦点切换不清空选择；按题保存草稿 |
| 已提交后看不到自己的理由 | 只返回当前密钥自己的评审记录，提交后展示原有选择与理由 |
| 错误密钥后无法直观恢复 | 中文错误提示与连接对话框；更新密钥后重新识别项目与角色 |
| 评审专用账号可能进入工程步骤 | reviewer 仅展示评审入口；API 继续拒绝实验、版本与 Trace 查询 |
| 自测可能被混入人工覆盖 | 新增独立 `self_review_votes` 表，自测不计入人工覆盖、不满足签署条件 |

浏览器使用 Chromium / Playwright，检查桌面与 390px 手机布局。前端所有来自资料或模型的字符串先做 HTML 转义；密钥保留在当前标签页，模型服务密钥不送前端。

## 模型失败与修复

旧版真实留出记录 [real-model-holdout.json](../artifacts/real-model-holdout.json) 保留原样，原来的 `block` 没有变成 `pass`。已经见过的 16 道题在 0.5 模板导入时明确标为 `development`，用于回归诊断。

这轮实际遇到了三类问题：

- `--api-key-file` 的公开配置问题被误当成索要真实秘密，模型拒答。
- 模型把内部证据编号 `E0` 当成用户答案。
- 改写原文时省略上下文参数的 `0` 和嵌入功能要求的模型类型。

中间版本 v3 只从选中的原文补全 CLI flag，没有覆盖拒答；v4 区分公开配置与真实秘密，修复认证参数，却出现其他主题退步。两份中间失败记录分别保存于 [v3](../artifacts/dogfood-intermediate-v3.json) 和 [v4](../artifacts/dogfood-intermediate-v4.json)。v4 的自动检查仍然拦截。

最终 `llm-grounded-v5` 采用明确的**原文问答契约**：真实模型选择证据行并决定是否拒答，服务器用选中的逐字原文作答，避免依赖不稳定的改写。原始模型草稿、处理契约、请求摘要、文档、模型 profile 和 Token 都保留。不是把答案标签塞进模型，也没有声称这等于自由生成文本的准确率。

| 当前回归对照 | 规则通过率 | P95 端到端耗时 |
|---|---:|---:|
| 原版本 `llm-grounded-v2` | 14 / 16，87.5% | 2283.25 ms |
| 原文优先版 `llm-grounded-v5` | 16 / 16，100% | 2251.25 ms |

自动回归检查通过；4 道无依据题均拒答。该轮对比标准在运行前已由工作台代码固定：最低 10 题、2 个主题、80% 通过率、最差组退步不超过 20 个百分点、P95 不超过 30 秒，不要求 holdout。没有拿这次回归通过取代原来的独立留出失败。

不能凭这 16 道已见题证明新领域泛化。原文是真实来源也不保证选对语义；多行跨段推理、复杂计算、不同语言和真实客户题仍需新的冻结题集与人工评审。数值 / 字符串匹配评测器不是语义判官。GPU 实际输出可能受批处理和缓存影响，这轮 v2 为 14/16，与历史 15/16 不同，不能把固定 seed 当作所有执行条件下的确定性保证。

## 开发者自测与人工验收

作者读取 16 对实际答案及参考文档后，按题写了诊断依据，再通过浏览器表单逐题提交 `reviewer_kind=developer_agent`，没有根据自动分数生成“人工票”。已见结果和作者角色使这次评审不具备独立盲化条件。

实际记录：**开发者自测覆盖 16/16，人工覆盖 0/16，人工验收未签署**。两道参数题更支持修复答案，其余题正确性相当。手工判断见 [逐题理由](../artifacts/dogfood-review-decisions.json)，真实输出、门禁与覆盖见 [dogfood-model.json](../artifacts/dogfood-model.json)。

浏览器验证按钮保持“待验收”；即使直接请求签署，API 也返回 409。自测不能替代人工评审，更不能代表真实客户签收。密钥身份与客户端声明的 human 类型本身也不证明评审者是独立真人。

## 如何复查

启动本地 API、worker 与模型后，打开 <http://127.0.0.1:8000/>。用技术文档模板走四步，或选择已保存的“公开技术文档 · 开发回归验证 / 16题”任务查看这次结果。旧 `/delivery.html` 等链接自动进入新工作台。

```powershell
.\check.ps1
node .\tests\browser_workspace.cjs smoke
node .\tests\browser_workspace.cjs quick
node .\tests\browser_workspace.cjs model
node .\tests\browser_permissions.cjs
node .\tests\browser_forms.cjs
```

`model` 会调用真实本地模型创建新的回归实验；快速演示不调用模型。权限测试创建独立测试项目；表单测试只保存浏览器草稿，不提交人审。显式的开发者自测重放命令需要一份实测报告和逐题人工核对的诊断文件，不能直接复用旧轮次的左右位置到新轮次。

```powershell
node .\tests\browser_self_review.cjs .\artifacts\dogfood-model.json .\artifacts\dogfood-review-decisions.json
```

这条命令只提交开发者自测、验证人工签署仍被拒绝，绝不提交 human 票。对应同一轮次已提交的题不会覆盖。新轮次必须重新读取实际左右答案并准备诊断文件。
